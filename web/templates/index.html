About APKAnalyzer

        
Open-source Android static analyzer with a focus on precision over noise.

        

          
How it works

          

          1. Extract — androguard parses DEX, apktool decodes resources.

          2. Build IR — a call graph + per-method CFG with a string pool.

          3. Reachability — only methods reachable from entry points are analysed.

          4. Taint analysis — sensitive sources (device id, location, user input) are traced through the call graph to security-critical sinks.

          5. Detector pass — 11 specialised detectors run in parallel: crypto, network, storage, WebView, secrets, deeplinks, intents/IPC, logging, native libs, obfuscation, privacy.

          6. Score — confidence is adjusted for library / test / debug context, then OWASP MASVS, CVSS, and CWE are attached.

          7. Report — JSON, HTML, SARIF (GitHub Code Scanning), or this dashboard.
          

        

        

          
Vulnerability classes covered

          
    
            
  • Hardcoded credentials, API keys, tokens (AWS/GCP/GitHub/Stripe/Slack/Twilio/SendGrid/Mailgun/Square/JWT/PEM)
    • 
            
  • Weak / broken cryptography — DES/RC4/MD5/SHA1, ECB, static IV, hardcoded keys, no padding, small key sizes, custom KeyStore bypass
    • 
            
  • Insecure communication — cleartext HTTP, custom TrustManager, hostname verifier stubs, weak TLS, missing pinning, network_security_config issues
    • 
            
  • Insecure storage — world-readable prefs, plaintext SQLite, allowBackup, external storage, key-store bypass
    • 
            
  • Insecure logging — Log.* with PII / tokens, printStackTrace, System.out
    • 
            
  • WebView issues — JavaScriptInterface, mixed content, debugging enabled, file:// URL load
    • 
            
  • Deeplinks — no auto-verify, fragment injection, scheme downgrade, OAuth hijack, JS-bridge abuse
    • 
            
  • Intent / IPC — mutable PendingIntent, intent redirection, sticky broadcasts, getParcelableExtra without class
    • 
            
  • Native libraries — missing PIE / NX / RELRO / stack canary, debug symbols shipped, runtime System.load from /sdcard
    • 
            
  • Obfuscation / anti-analysis — dynamic DEX, reflection-heavy code, root / emulator detection
    • 
            
  • Manifest misconfiguration — debuggable, exported components without permission, custom permissions with normal protectionLevel, low targetSdk, missing networkSecurityConfig, tapjacking risk
    • 
            
  • Privacy — sensitive data flowing into log / network / storage sinks, third-party SDK inventory
